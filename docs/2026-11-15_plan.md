# SA Mentoring Program — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Написать теоретические материалы программы: шпаргалка framework + 10 файлов модулей.

**Architecture:** Один HTML-файл на модуль, все по одному шаблону. Каркас страницы — как в `html/session-01.html`. Шпаргалка задаёт названия шагов framework; файлы модулей используют их без изменений.

**Tech Stack:** HTML + общий `html/style.css`, диаграммы Mermaid (`<pre class="mermaid">`). Git: commit прямо в `main` + push, сайт публикуется автоматически. Тестов нет: проверка = Grep по структуре + вычитка.

**Spec:** `docs/2026-11-15_design.md`

## Global Constraints

- Язык: русский. Стандартные архитектурные термины не переводить (trade-off, NFR, ADR, SLO, assumptions, constraints, risks, stakeholders, business drivers, scope, quality attributes, failure modes).
- Стиль: кратко, таблицы и схемы вместо сплошного текста. Формат = материал для обсуждения, не лекция.
- Читатель: senior/lead инженер. Не объяснять базовое (что такое индекс, очередь, REST).
- Домен нейтральный. Data Engineering: основной объём в модулях 5 и 6; в остальных — ровно один пример в своём разделе.
- Без привязки к облаку и продуктам. Продукт можно назвать только как пример класса.
- Кейс: один сквозной, уже есть у автора. В материалах называть «сквозной кейс», детали кейса не придумывать.
- Объём файла модуля: без лимита слов.
- Чтение: раздела нет. Ссылки на книги в файлах модулей не давать.
- Папка: `html/`. Новая страница → ссылка в `html/index.html` и «Назад / Дальше» в `<nav>` соседних страниц.

## Шаблон файла модуля

Структура ниже записана в Markdown для краткости. В HTML: `#` = `<h1>`, `##` = `<h2>`. Ровно эти 6 заголовков `<h2>`, в этом порядке. Исключение: в модуле 1 перед «Зачем» стоит дополнительный `<h2>` «Старт программы» (знакомство, формат, выпускная работа), и ключевых идей больше 7:

```markdown
# Модуль N. <Тема>

Шаги framework: <номера и названия>

## Зачем
2–3 предложения: какую ошибку мышления модуль устраняет.

## Ключевые идеи
4–7 идей. Каждая: тезис + таблица или схема. Привязка к вопросу шага framework.

## Пример: Data Engineering
Один пример из data-платформ. (Модули 5–6: раздел шире, до 300 слов.)

## Типовые ошибки
Таблица: ошибка senior/lead инженера | почему возникает | что делать.

## Вопросы для обсуждения
5–7 открытых вопросов. Без готовых ответов.

## Подготовить к следующему модулю
Список: (1) прочитать PPT-материалы следующего модуля; (2) прочитать конспект следующего модуля; (3) сквозной кейс: какой артефакт шага framework менти делает к следующему модулю.
```
